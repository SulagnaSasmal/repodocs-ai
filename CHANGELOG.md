This changelog tracks product-facing changes to RepoDocs AI.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).
This project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.2.7] - 2026-11-28

Fixes from the v1.2.6 fresh-agent release check, which used the Velo Payments API (OpenAPI 3.0.2, 100 operations) and a small synthetic spec for the features Velo lacks, with 496 deliberate breaks and 72 legitimate edits. v1.2.6 failed the run on 365 breaks, warned on 24, missed 107 and rejected 4 legitimate edits; its generated docs failed `validate` (67 errors) and the CI lint step (34 errors) on Velo as generated. On v1.2.7 the generated docs pass both, and against a baseline generated by v1.2.7 the same run fails on 460 breaks, warns on 25, misses 10 (unverifiable, by design, or no longer possible) and accepts all 72 legitimate edits. See `.github/release-checks/2026-11-28-v1.2.6.md`.

### Security

- Control plane: changes to users and keys go through a lock in Redis. Under concurrent requests, a revoked key could come back to life and users created at the same moment could be lost; neither can happen now, across instances too. Key use is recorded apart from the user list.
- Control plane: once any user exists, a key is always required. Revoking or disabling every key no longer reopens the no-key mode, and the last working admin key cannot be revoked.
- Control plane: it refuses to start with `REPODOCS_TRUST_PROXY=1` and no key, since a proxy on the same machine looks local. `Via`, `X-Forwarded-Host` and `X-Forwarded-Proto` also mark a request as proxied. SECURITY.md no longer claims every proxied request is detected.
- Control plane: a valid key keeps working during a failed-attempt lockout; wrong keys sent to `/auth/status` count toward it; an operator with no `service_scope` can run no jobs; user names are unique regardless of case; each user can have at most 5 jobs waiting; 401 responses carry the security headers; the bootstrap key's hint is not stored. Bootstrap keys built from words, repeats or runs (`repodocs-ai-control-plane-key`, `Summer2026!Summer2026!xy`, `aaaaaaaaaabbbbbbbbbb...`) are refused.
- Generator: it never writes through a symbolic link in the output folder; refuses specs over 50 MB or that expand to more than 5 million values (a YAML alias bomb); strips HTML and script URLs from frontmatter values; and quotes `!` in form-encoded fields too.
- Validators and generator: code fences and HTML tags are matched in time proportional to the text, so a long run of backticks or unclosed tags can no longer stall them (50,000 backticks took 4.6 s; now 0.7 s). Operations are looked up by index, so a 20,000-operation spec generates in 5 s (was 78 s) and validates in 33 s (was over 120 s).
- Quality check: `<scr<script>ipt>`, `srcset` script URLs, `<applet>`, `<portal>`, `<frame>`, HTML or script URLs in the frontmatter, and block elements left open are errors.

### Added

- The generator and the OpenAPI check share one module of example rules (`scripts/lib/schema-values.mjs`), so a generated example never fails the check.
- Spec examples that break their own schema are corrected, and the doc lists each change: readOnly fields leave requests, writeOnly fields leave responses, exact conversions (`"12"` to `12`, `12` to `"12"`, a date-time where a date is expected) are made, values of the wrong type, too long, outside an enum or pattern, or `null` are replaced, and missing required fields are added at any depth. Built values meet `maxLength`, `pattern` (sampled from the regular expression), `multipleOf` and `minItems`.
- Generator: cookie parameters (a section and `--cookie`), non-JSON responses as text with an `Accept` header, alternate request and response content types, response headers such as `Link`, callbacks, allowed values of array items, `Pattern` notes, body rows six levels deep, every security scheme in the overview with the operations that need none, and separate files for routes that would share a name.
- Generator: spec HTML formatting (`<p>`, `<b>`, `<i>`, `<code>`, `<a href>`, lists) becomes Markdown, and spec Markdown is tidied to pass markdownlint: one list marker and one emphasis style, blank lines around headings, fences and lists, no trailing spaces, unclosed fences closed, in-page anchor links reduced to their text, and summaries without a trailing full stop.
- OpenAPI check: `null` where the spec does not allow it; RFC 3339 dates and date-times; patterns; readOnly and writeOnly at every depth and in every `oneOf` option; the body's top-level type; path, header and cookie values; unknown, invalid and missing cookies; form-encoded fields; OAuth scopes in the authentication section; a lowercase method; the wrong word or an empty value in `Authorization`; missing rows for required nested body fields; length notes; a `oneOf` field typed as a single type; an error status shown as the success example; a JSON body for a response that has none or is not JSON; success codes in Error Codes; every server named in the overview; renamed sections; every curl in the Request Example, and curls elsewhere in the doc.
- OpenAPI check, guides: each curl is checked against the operation it calls (query parameters, credentials, JSON body), `$BASE_URL` calls included; `wget`, `fetch`, Python `requests` and inline-code calls must use a defined path and method; an endpoint named in prose that the spec does not have is a warning.
- Warnings: a missing Summary, Request Example, Response Example or Error Codes section, or overview Base URL; a parameter row that does not list its allowed values; a Markdown image from another site; a `<name>` placeholder in the request URL.
- Quality check: `T.B.D.`, "to be determined", "description goes here", "fill me in", `?? … ??` and a line that says only "Coming soon" are placeholders.
- The Velo Payments API as an eleventh third-party fixture, the synthetic ledger spec as a probe fixture, a markdownlint run over the generated docs of every fixture, and probe tests for every finding.

### Changed

- `TBD` counts as a placeholder only in prose, so a code span such as `` `TBD` `` (an enum value, say) passes.
- A shell prompt or comment lines before a curl no longer hide it; `curl -G` data is read as the query; a JSON body printed over several lines is read whole; tables without outer pipes are read; "One of: `a`, `b`" counts as a list of allowed values; OAuth scopes written in prose are read.
- The overview check accepts any scheme an operation uses, such as HTTP Basic on a token endpoint, and lists of operations that need no authentication.
- A note copied from a parameter's own description is not compared as a constraint note.
- A doc with more than one curl in its Request Example no longer gets a warning: every curl is checked.
- Each problem is reported once.

## [1.2.6] - 2026-11-28

Fixes from the v1.2.5 fresh-agent release check, which used the Discourse API (OpenAPI 3.1, 84 operations), 228 deliberate breaks and 40 legitimate edits. v1.2.5 failed the run on 167 breaks and rejected 3 legitimate edits. v1.2.6 fails it on 197, warns on 19 more, and rejects 1 legitimate edit, by design: a `stable` doc with no `reviewed_by`. See `.github/release-checks/2026-11-28-v1.2.5.md`.

### Security

- A multipart example that uploads a real local file, such as `-F "file=@/etc/passwd"`, fails the OpenAPI check. Generated multipart text fields use `--form-string`, so a value starting with `@` or `<` is sent as text, never read from disk.
- `!` in generated curl examples is quoted, so shell history expansion cannot change a value.
- The quality check catches script links split by a newline inside a quoted attribute, in `formaction`, `xlink:href`, `poster` and other attributes, and as autolinks; event handlers after `/` or a quote; and `style` attributes that load a URL. Images from another site are a warning.
- Control plane: bootstrap keys that run along the keyboard, the alphabet or the digits are refused.
- The CI workflow that `init` writes now lints the Markdown with a pinned `markdownlint-cli`.

### Added

- OpenAPI 3.1 support in the generator: `examples`, `const`, type arrays such as `[string, "null"]`, and more formats (`time`, `uri-reference`, `hostname`, `ipv4`, `ipv6`, `byte`). Example numbers respect minimum and maximum, and strings meet `minLength`.
- Multipart request bodies: file fields get `-F "name=@<file>"`, other fields `--form-string`, and the OpenAPI check reads each field's name, type, allowed values and whether it is required.
- An operation with no 2xx response says so instead of showing an invented example. Other servers are listed under the base URL. With no security scheme, credential-like header parameters such as `Api-Key` are pointed out for SME review.
- OpenAPI check errors: a second Endpoint, Request Example, Response Example, Request Body or Error Codes section; a wrong value in any JSON block of the Response Example or in a `~~~` fence; an indented code block in place of a fenced one; Endpoint URL placeholders that do not match the spec's path parameter names; `-XPOST`-style methods; a request body on an operation that takes none; Required values other than yes or no; declared fields inside objects that also allow other keys; and curl calls in guides and overview pages to a path or method the spec does not define.
- Quality check errors: a heading with no space after `#`, a heading indented into a code block, a table separator with the wrong number of cells, an unclosed HTML comment, `TBD` in any case, and `<your-…>` placeholders in prose.
- Warnings: a Response Example with no `Status:` line, a Request Example with no curl or with more than one, an auth header the spec uses on other operations but not this one, a page with no `#` title, and a Swagger 2.0 file in the specs folder, which is now reported instead of skipped without a word.
- The Discourse API as a tenth third-party fixture, and probe tests for every new check.

### Changed

- The Required column accepts `required`, `true` and `mandatory` as yes, and `optional` and `false` as no.
- `<insert …>` and `{{…}}` count as placeholders only in prose, so a Handlebars or template example inside a code block passes.
- The suspicious-status heuristic no longer runs on docs that are compared with a spec, where the spec decides the status.
- A hand-written endpoint doc that leaves out optional request fields gets a warning instead of an error; a missing required field is still an error.
- A spec that cannot be parsed gives one line naming the file and the YAML or JSON error, not a stack trace.
- A parameter with no description says `Needs SME input` instead of repeating where it is sent.

- The overview lists keys that must be sent together; endpoint docs show a one-line summary of each scheme.

- Overview headings skipped levels; `<br />` and HTML comments showed as text; generated docs failed the markdownlint config `init` ships.
- Pipes in parameter names, backticks in enum values, newlines in summaries and ```` ``` ```` inside JSON broke the Markdown.
- Non-JSON request bodies were written as `--data-binary @<file>`, which a shell reads as a redirect.

## [1.2.4] — 2026-11-28

Closes the items the 1.2.3 security audit left open. See `.github/release-checks/2026-11-28-security-audit.md`.

### Security

- Control plane operators see only the runs they started and the artifacts of jobs their scope allows; admins see everything.
- Rate limits are counted in Redis and shared by every instance. `REPODOCS_TRUST_PROXY=1` applies them per client behind a proxy. Requests that arrive through a proxy are never treated as local, so a proxy on the same machine cannot reopen a server that has no key.
- Every GitHub Action is pinned to a commit SHA, in this repository and in the workflow `init` writes, which also gets a read-only token.
- The docs website sets a Content-Security-Policy and referrer policy in each page, with per-page script hashes.
- KaTeX override clears the last `npm audit` advisory.

### Changed

- `@anthropic-ai/sdk` 1.14, `redis` 6 and `js-yaml` 5. The agent's default model is `claude-opus-5-5`; set `REPODOCS_AI_MODEL` to use another.
- `archive/` is removed. Nothing used it; Git history keeps it.

### Fixed

- A job taken off the queue while a server was shutting down was lost. It is now put back for another worker.
- The control-plane dashboard failed for operators because it always asked for the admin-only user list.
- The quality check's summary line now names the unsafe-HTML check.

## [1.2.3] — 2026-11-28

Fixes from the v1.2.2 fresh-agent release check, which used the Adyen Checkout API and 101 deliberate breaks. v1.2.2 failed the run on 59 of them; v1.2.3 fails it on 96. See `.github/release-checks/2026-11-28-v1.2.2.md`.

### Added

- The OpenAPI check compares the JSON type of every example value with the schema, in request, response and error examples.
- `Default:`, `Format:`, `Minimum:` and `Maximum:` notes in Request Body rows and parameter tables are compared with the schema, as are plain allowed-value lists written by hand.
- The request example's credentials (`-u`, `Authorization: Bearer`) and `Content-Type` header are compared with the spec, and so is a Request Body that says the body is required or optional.
- `TODO`, `TBD`, `FIXME`, `<insert …>`, `{{…}}` and lorem ipsum fail the quality check.
- `last_reviewed` must be a date that exists on the calendar and is not in the future.
- A warning when a hand-written doc that follows a template drops some of its sections, and when the request URL still has a `{name}` placeholder.
- The validate summary gives the reason for each skipped check.
- The Adyen Checkout API as a third-party fixture, with probe tests for every new check.

### Changed

- The "POST returning 200" heuristic applies to hand-written docs only.
- Path and query parameters with no example appear as `{name}` in the curl URL instead of `value`.
- The generator writes allowed values in backticks, so prose in a spec's description is never read as an enum.
- When a spec's own example gives a number as a string, the generator shows the number and says so.
- The OpenAPI and version checks in `npm run validate` cover every example folder that `init --with-examples` copies.

### Security

From a security audit on 2026-11-28. See `.github/release-checks/2026-11-28-security-audit.md`.

- Generated docs escape HTML from the spec outside code and drop `javascript:` links, so a spec cannot put script on a docs site. The quality check fails hand-written docs with `<script>`, `<iframe>`, inline event handlers or script links. This also makes types such as `array<string>` show on the page.
- Control plane: with no key configured, only requests from the same machine are accepted, where anyone on the network could previously create an admin. Bootstrap keys under 24 characters and placeholders such as `replace-me` stop the server from starting.
- Control plane: dashboard output is escaped and runs under a nonce-based Content-Security-Policy; the API key is kept for the browser tab only. Security headers and `Cache-Control: no-store` on every response.
- Control plane: request bodies are limited to 64 KB; requests are limited per address, with a one-minute lockout after 10 wrong keys; malformed JSON gets 400 and server errors no longer return internal details.
- Control plane: `service_scope` matches job names exactly, where `a` used to allow `analytics`, `agent` and `automation`. The last active admin cannot be demoted or disabled. Keys are compared in constant time. `/health` no longer shows run details, user names, paths or the Redis URL, and the Redis password no longer appears in the log.
- Control plane: the job worker has its own Redis connection, so requests no longer wait up to a second behind it each, and a Redis outage is logged instead of crashing the server.
- Docker: the container runs as the `node` user; the compose stack requires `REDIS_PASSWORD` and a bootstrap key, keeps Redis off the host, and publishes the control plane on 127.0.0.1 only.
- `.env` files, keys and `.npmrc` are ignored by Git and Docker.
- Every workflow's token is read-only, and workflow inputs reach scripts through the environment instead of the script text.
- Website: 49 dependency advisories (18 critical) resolved with `npm audit fix` and overrides for packages Docusaurus pins; Dependabot now watches the website.

### Fixed

- The bundled examples failed the OpenAPI check after `init --with-examples`, and their owners were missing from the owners registry.
- Parameter names written in backticks in hand-written tables were not recognised.
- A `##### Authentication` heading copied from a spec description hid the overview's Authentication section from the check; the generator now demotes such headings.
- Newlines and pipes in spec descriptions broke table rows; keywords next to `$ref` were ignored; deprecated parameters and fields were not marked; `last_reviewed` used the UTC date rather than the local one.
- Validators write their report in one call and set the exit code, so no lines are lost when output goes to a pipe.

## [1.1.0] — 2026-11-27

This release makes validation work on your own docs and makes the README match what the tool does. The issues were found by following the README as a first-time user and as a fresh AI agent, using the public Swagger Petstore spec.

### Added

- `npm run validate:docs -- <docs> --specs <specs>` runs the frontmatter, structure and quality, OpenAPI example and API version checks on your docs, and reports PASS, WARN, FAIL or SKIP for each.
- Bootstrapped docs repositories get a CI workflow (`.github/workflows/docs-validate.yml`) that runs those checks on every pull request.
- Generated docs document header parameters, including `Idempotency-Key` in the payments example.
- The quality check warns about placeholder example values left by the generator.
- Dependabot updates for npm and GitHub Actions.
- A "What It Does Not Do" section in the README.

### Changed

- Every check names the folder it checked. Spec checks without `--specs` report SKIP, never PASS.
- The quality check lists what it checks instead of reporting "MERGE-SAFE and PUBLICATION-READY".
- The OpenAPI and version checks count only the docs they actually compared.
- Curl examples include credentials only when the spec defines security, using the scheme's real header.
- Endpoint titles fall back to `operationId`; the overview uses the spec's `info.title`.
- The bootstrapped CODEOWNERS contains commented example rules instead of this repository's owner.
- README claims now match the code: exports write files and upload nothing, generated docs are drafts for SME review, and the control plane, deployment manifests and site starters are marked experimental.
- `js-yaml` moved to runtime dependencies. Upgraded `vitest` to 5 and `markdownlint-cli` to 0.50; the test suite now needs Node.js 22 or later.
- Experimental parts moved to `experimental/`: control plane deployment files, site starters, and GitLab and Bitbucket CI. See `experimental/README.md`.
- Moved the old static site, demo video assets, pricing notes and internal planning docs to `archive/`, out of the published site.

### Fixed

- `validate:quality` ignored the folder passed to it and validated this repository's examples instead.
- The OpenAPI check skipped request and response schemas defined through `$ref`.
- `allOf` schemas lost properties and required fields in generated examples.
- A 204 response got an invented response body.
- A missing spec file printed a stack trace, and Authorization headers could appear twice in curl examples.
- 16 of 20 reported dependency vulnerabilities, including both critical ones. 4 low-severity advisories remain in a markdownlint dependency.
